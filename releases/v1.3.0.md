# naluz/framework v1.3.0 — optional event streaming (Redis Streams, RabbitMQ, Kafka)

Build event-driven systems: one service publishes an event, any number of other services react to it. Nothing here is loaded or
required unless you use it.

## Added

- **`Naluz\Messaging`**
  - `EventBus::publish($topic, $payload, …)` and `EventBus::dispatch(PublishableEvent)` publish events.
  - `Consumer` + `Subscriber` handle them (`php naluz messaging:consume orders.placed`). Subscribers are registered per topic (or pattern such as
    `orders.*`) in `config/messaging.php`.
  - Consumer **groups**: every group receives every event; instances in the same group share the work.
  - **At-least-once** delivery with per-group **retries** (`--tries`, `--backoff`) and **dead-letter topics** (`<topic>.dlq`) carrying the error.
  - Optional **HMAC-SHA256 signing** (`MESSAGING_SIGNING_KEY`, with key rotation): unsigned or tampered messages are dropped. Messages are only parsed
    as JSON (never unserialised), size- and depth-limited, and the `type` field is never instantiated. Topic names are validated.
- **Drivers** (`MESSAGING_CONNECTION`)
  - `memory`: in-process, for tests and local development.
  - `redis`: Redis Streams (Redis 6.2+) through the framework's own client, no extra dependency. Consumer groups, `XAUTOCLAIM` takeover of messages a
    crashed consumer never acked, capped stream length.
  - `rabbitmq`: needs `composer require php-amqplib/php-amqplib`. Durable topic exchange, one durable queue per group and topic.
  - `kafka`: needs `ext-rdkafka`. Idempotent `acks=all` producer, consumer groups with manual offset commit, message keys for ordering.
- Commands: `messaging:consume`, `messaging:declare` (create groups/queues before the first publish), `messaging:publish`, `make:subscriber`.

## Notes

- Subscribers must be **idempotent**: a message can be delivered more than once.
- RabbitMQ drops messages nobody is bound to yet, so run `messaging:declare` (or start the consumer) before the first publish.
- Redis Streams, RabbitMQ and Kafka are tested as follows: Redis against a real `redis-server`; RabbitMQ and Kafka against stand-ins for
  php-amqplib and ext-rdkafka (no broker in CI). Try them against your own broker before relying on them in production.

## Upgrading

```bash
composer require naluz/framework:^1.3.0
```

No breaking changes.
